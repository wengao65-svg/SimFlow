# MLP 参考标签一致性

## 目的与适用范围

本参考约束的是 MLP 训练用 DFT 标签的**标签协议（label protocol）**，不是具体 DFT 引擎。它适用于任何用于 MLP 标注的 DFT 引擎（VASP、CP2K、Quantum ESPRESSO、ABACUS、自定义引擎）。引擎特定的文件格式、标签名、生成命令、dry-run 机制由对应引擎 skill 承担；本参考只规定跨引擎不变的方法论契约。

机器学习势函数从数据集中学习一张势能面（PES）。一个单保真数据集内的所有 `(结构, 能量, 力, 应力)` 标签必须来自同一张 PES。混入不同协议的标签会让模型去拟合一个不存在的、内部矛盾的势能面——这是 MLP 训练中最隐蔽的系统性误差来源，且会通过主动学习传播到后续轮次。

## 1. 单一参考协议

一个单保真数据集对应一个明确的 label protocol。协议由科学设置（见第 3 节）与赝势/基组分配（见第 2 节）共同定义；二者任一变化即产生新协议。

- 记录协议标识（建议用归一化科学输入的 SHA256 指纹）与必要的输入指纹。
- 同一数据集内所有作业的科学输入指纹必须一致；不一致即判违规。
- 未知或不兼容的协议不得静默合并。开源数据集原始协议不可知时，记录"未知"；若需合并，在自协议下对子集重新标注是最安全路径。

## 2. 结构、赝势与原子顺序

- 结构元素与赝势/基组分配必须匹配：每个结构按其元素顺序配置对应赝势，禁止用一个全局赝势配置覆盖多种元素组合的结构。
- 同一元素的赝势/基组变体在所有元素组合中保持一致。
- 规范化元素顺序（如 `dpdata sort_atom_names(type_map=...)`）会静默重排原子；重排时必须保存 `structure_to_source_atom_index` 索引映射，且映射必须是 `0..N-1` 的完整置换。NEB、phonon 等需要原子序对应的工作流尤其敏感。

## 3. 科学设置与机器设置

- 影响能量、力、virial/stress 定义或数值精度的设置属于**科学协议**：截断能/基组尺寸、SCF 收敛阈值、smearing/占据方式、交换关联泛函、赝势族、k 点密度策略、对称性处理、是否相对论/DFT+U/色散/杂化。这些标签一旦变化，PES 就变了；整个数据集必须单一。
- 并行、主机、队列和可执行路径属于**运行元数据**：不改变 PES，允许逐作业变化，不进入协议指纹。
- 具体哪些标签归入哪一类、默认值清单、取值策略由对应引擎 skill 解释（见第 6 节）。

## 4. 数据集边界

- 生产标签、收敛测试、性能测试和替代协议分别记录，属于独立的证据角色。
- 只有属于目标协议并通过标签检查的结果才能进入数据集。任何不属于冻结协议指纹的作业都被排除。
- 研究目标升级需要更紧的科学设置时，新建数据集并显式记录与旧数据集的协议差异，而非在原数据集上混入。

## 5. 主动学习与跨数据集连续性

- 后续主动学习标签继承当前协议：从 iter0 到 iterN，科学输入指纹不变。
- 协议改变时建立新数据集/模型 lineage：旧模型不再适用于新协议下的数据，必须从头重训。
- 开放数据协议未知时记录"未知"，不得推测后当成已知使用；重新标注是最安全路径。

## 6. 引擎路由

- VASP → `simflow-vasp`
- CP2K → `simflow-cp2k`
- Quantum ESPRESSO / ABACUS / 自定义引擎 → 查阅官方文档并显式记录引擎特定的执行细节（文件格式、标签名、版本、赝势文件 hash）作为溯源证据；不得从其他引擎经验外推。

无论引擎是否有 SimFlow skill，本参考的协议条款均适用——一致性要求不因引擎不同而放松。
