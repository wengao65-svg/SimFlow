# Scale-Dependent Contributions

Use alongside the relevant physical, method, resource, or reliability guidance
when system size, time, chemical coverage, or accessible conditions matter to
the contribution. Scale is a cross-cutting attribute, not a fixed paper type.

## Explain What Scale Changes

Identify the phenomenon or inference made accessible: collective behavior,
domain growth, rare-event sampling, a realistic interface, or a new statistical
regime. Distinguish faster computation from a demonstrated change in what can
be learned. A capability benchmark is legitimate, but do not add an unobserved
physical discovery to make the scale seem significant.

Use size/time comparisons, overlapping reference calculations, independent
trajectories, or condition maps when they support the particular claim. Explain
why an earlier regime would miss the result only if that comparison is supported.
Do not assert conventional AIMD is unable to access it without a justified basis.

## Evidence and Presentation

Report actual sizes, durations, sampling, and costs relevant to the conclusion.
Distinguish measured from extrapolated performance. Address size/time dependence
and remaining convergence uncertainty; reaching a large scale does not establish
convergence. Validate the model in relevant states, not only small static examples.

Integrate this evidence into the main argument rather than requiring a workflow,
validation, large simulation, mechanism, map, and prediction as six separate
figures. End with the demonstrated capability or scientific consequence, not
atom count alone or a compulsory future prediction.
